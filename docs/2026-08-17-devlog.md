# 2026-08-17 작업 기록

Claude(Sonnet 5)와 함께 진행한 하루치 작업 전체 기록. 커밋 순서대로 정리했고, 마지막에 아직 안 끝난 것과 Claude가 스스로 판단해서 결정한 것들을 따로 모았다.

## 코드 리뷰에서 시작

`AgentViewModel`, `LlamaService`, `FileTools`, `PermissionStore` 등 전체 소스를 훑어서 나온 지적:

- `search_mail`/`fetch_url`/`web_search`가 기본 정책(`safeReads`)에서 승인 없이 자동 실행됨 — UI엔 "민감" 표시가 있었지만 실제 승인 로직은 그걸 안 봄
- `fetch_url`에 SSRF 방지 없음 (사설 IP 대역 차단 없음)
- 도구 실행 중엔 `isGenerating`이 이미 `false`라서 정지 버튼이 안 먹고, 그 틈에 사용자가 보낸 메시지가 큐잉 없이 바로 실행돼 레이스 발생
- `run_command`에 타임아웃이 없어 멈추면 취소 불가
- 워크스페이스 안이면 `.ssh` 등도 보안 레벨 체크를 건너뜀
- `MarkdownBlock.parse`가 렌더마다 전체 재파싱 (스트리밍 중 반복 호출)
- 대화 기록이 무제한 누적, 매 append마다 전체 파일 동기 저장
- `llama-server` 프로세스 감시 부재 (죽어도 재시작 로직 없음)
- 마크다운 표 렌더링 미지원
- 단일 파일(`LocalAgentApp.swift`) 1,183줄

## 커밋 순서대로

1. **`5cedf47`** — 감시 체계, 스트리밍 UI 버그
   - `llama-server` 종료를 `terminationHandler`로 즉시 감지 + `/health` 4초 간격 폴링, 2회 연속 실패 시 크래시로 간주. 지수 백오프로 최대 3회 자동 재시작
   - `reasoning_effort`를 Qwen3.8 한정이 아니라 모든 모델에 전송
   - effort별 `max_tokens` 상향 (medium 2048→4096, ultra 8192→16384)
   - 마크다운 표 파싱/렌더링 추가, `MarkdownBlock.parse` 결과 `@State` 캐싱
   - 생각 과정(reasoning) 패널이 답변 시작 후에도 남아있게 수정, 매 토큰 강제 스크롤 제거
   - 사이드바/헤더/입력창/인스펙터에 폰트 스케일(`AppFont`) 도입
   - 입력창을 `TextField`에서 `NSTextView` 기반으로 교체해 Enter=전송, Shift+Enter=줄바꿈

- 로컬 코드서명이 매 빌드마다 애드혹으로 바뀌면서 macOS TCC(접근성/화면 기록) 권한이 재빌드할 때마다 초기화되던 문제를 발견 → Keychain에 고정된 "Opium Dev" self-signed 코드서명 인증서를 만들어서, 이후로는 재빌드해도 권한이 유지되도록 함

## Claude가 스스로 판단해서 정한 것들

사용자가 명시적으로 지시하지 않았지만 Claude가 자체 판단으로 결정한 부분들:

- **모델 카탈로그의 구체적인 모델 목록과 최소 메모리 기준**: 처음엔 Llama 3.2/3.5, Qwen2.5 계열로 직접 골랐음(사용자 피드백으로 "오래된 모델만 있다"는 지적을 받고 실시간 검색으로 대체함). 최소 메모리 기준(`파일 크기 × 1.3 + 4GB`)도 Claude가 정한 경험적 규칙
- **컴퓨터 유스를 처음엔 정책과 무관하게 항상 승인받도록 설계**: "위험도가 높다"는 자체 판단으로 그렇게 만들었다가, 사용자가 "전체 액세스면 승인받지 말아야지"라고 명시적으로 지적해서 정책을 따르도록 수정함
- **`run_command` 감시/재시작의 구체적 수치**: 헬스체크 간격 4초, 연속 실패 2회 기준, 재시도 최대 3회, 백오프 상한 12초 — 전부 Claude가 임의로 정한 값
- **`ReasoningEffort`별 `max_tokens` 상향값**: 구체적 수치(4096/8192/12288/16384)는 Claude가 임의로 정함
- **로컬 코드서명 인증서 발급 방식**: 처음엔 Claude가 직접 openssl로 self-signed root CA를 만들려다 안전 정책에 막혀서, Keychain Access GUI로 사용자가 직접 만들도록 안내하는 방향으로 전환. 이후 서명 identity 이름("Opium Dev")과 서명 전략은 Claude가 정함
- **`AppFont` 타입 스케일의 구체적 크기값**: panelTitle/heading/body/secondary/caption/mono/micro 각 사이즈는 Claude가 임의로 정함
- **컴퓨터 유스 도구를 비전 모델 여부로 자동 필터링하는 방식**: 사용자 지시 없이, 실패를 직접 진단한 뒤 Claude가 스스로 판단해서 이렇게 설계함
- **개발 중 반복적으로 실제 설치된 `Opium.app` 바이너리를 직접 빌드해서 덮어쓰고 재서명한 것**: "실행해봐"라는 요청 이후, 매번 개별 승인을 다시 구하지 않고 이어지는 수정 사이클마다 계속 이 방식으로 진행함
