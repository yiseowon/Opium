# Opium 제품 전략 및 개발 로드맵

## 1. 제품 한 줄 정의

**Opium은 Mac에 있는 모델과 데이터를 연결해 정보를 정리하고, 사용자가 승인한 작업을 안전하게 실행하는 macOS 네이티브 로컬 AI 에이전트 플랫폼이다.**

단순한 로컬 LLM 채팅 앱이 아니라 다음 세 가지를 제품의 중심으로 삼는다.

1. 기술 지식 없이도 로컬 모델을 설치하고 실행할 수 있다.
2. Mail, Calendar, Reminders, Finder 등 macOS 앱과 데이터를 연결한다.
3. AI가 실제 작업을 수행하되 민감한 행동은 사용자 승인을 받는다.

## 2. 제품 원칙

### 2.1 Local First

- 메일, 메시지, 연락처, 일정, 문서 등 개인 데이터는 가능한 한 로컬 모델로 처리한다.
- 클라우드 모델을 선택하는 경우 외부로 전송되는 데이터와 목적을 실행 전에 표시한다.
- 작업 기록, 개인 메모리, 임베딩과 인덱스의 기본 저장 위치는 사용자 Mac으로 한다.

### 2.2 완전한 GUI 경험

- Homebrew, 터미널, 모델 파일 구조를 몰라도 설치부터 채팅까지 완료되어야 한다.
- 오류 메시지는 명령어 출력이 아니라 원인과 해결 버튼을 제공한다.
- 모델 다운로드, 검증, 로드, 중지, 교체, 삭제를 앱 안에서 처리한다.

### 2.3 읽기와 실행의 분리

모든 기능은 다음 단계로 나눈다.

1. **관찰:** 필요한 데이터 읽기
2. **제안:** 정리·전송·삭제·변경 예정 사항 표시
3. **실행:** 권한 정책에 따라 자동 수행하거나 사용자 승인 후 수행

### 2.4 복구 가능성

- 영구 삭제보다 보관 또는 휴지통 이동을 기본값으로 사용한다.
- 가능한 작업은 Undo를 제공한다.
- 모든 실행 내역은 감사 로그에 남긴다.
- Kit 설치와 업데이트는 실패 시 이전 상태로 복구할 수 있어야 한다.

### 2.5 측정 가능한 개선

- “더 똑똑하다”는 설명 대신 성공률, 토큰, 속도와 도구 호출 수로 증명한다.
- Kit을 구현하기 전에 평가 데이터와 성공 기준을 먼저 고정한다.

## 3. 최우선 사용자 경험

첫 사용자가 5분 안에 다음 과정을 끝내는 것을 첫 제품 목표로 한다.

```text
Opium 실행
  → Mac 사양 자동 분석
  → 추천 모델 선택
  → GGUF 다운로드
  → 자동 검증 및 로드
  → 첫 대화
```

첫 화면에서는 복잡한 모델 이름보다 용도 중심 선택지를 제공한다.

| 선택지 | 설명 |
| --- | --- |
| 빠름 | 적은 메모리와 빠른 응답을 우선 |
| 균형 | 대부분의 사용자에게 권장 |
| 품질 | 더 많은 메모리를 사용해 품질 우선 |
| 직접 선택 | 모델과 Quant를 직접 선택하는 고급 모드 |

Hugging Face 전체 검색은 고급 기능으로 제공하고, 기본 화면은 Opium이 검증한 소수의 GGUF 모델만 추천한다.

## 6. P1 — Kit 시스템

### 6.1 최소 Kit 규격

초기 규격은 단순하게 유지하고 실제 요구가 확인될 때 확장한다.

```json
{
  "id": "com.example.kit",
  "name": "Example Kit",
  "version": "1.0.0",
  "author": "Example",
  "description": "Kit description",
  "minOpiumVersion": "0.3.0",
  "permissions": [],
  "skills": [],
  "tools": [],
  "mcp": [],
  "dependencies": [],
  "entrypoint": null,
  "entitlement": "free"
}
```

확정할 규칙:

- [ ] Kit ID와 semantic version
- [ ] Opium 최소·최대 호환 버전
- [ ] author와 배포자 식별
- [ ] permissions 선언
- [ ] Skill과 prompt 로딩 순서
- [ ] MCP 서버 실행 규칙과 생명주기
- [ ] Kit 간 의존성 및 충돌 해결
- [ ] 파일 무결성 해시와 배포자 서명

### 6.3 기본 Kit 역할

#### Adrenaline Kit

목표: 어려운 작업을 끝까지 완수하는 실행력 향상.

- 도구 선택
- 계획·재계획
- 실패 원인 분석과 제한된 재시도
- 결과 검증
- 다단계 작업 진행 상태 관리
- 작업 완료 조건 확인

#### Caffeine Kit

목표: 긴 작업에서 집중력과 효율 유지.

- context 선별과 압축
- 중요한 사실과 결정 보존
- 중복 도구 호출 방지
- 검색 query 분해와 결과 reranking
- 중단된 작업 복구
- token 예산 관리

#### Melatonin Kit

목표: 백그라운드와 저우선순위 작업을 조용하고 저렴하게 처리.

- 예약 작업
- 낮은 자원 사용 모드
- 알림을 최소화한 백그라운드 처리
- 여러 결과를 압축한 최종 보고
- 실패 시 다음 실행으로 안전하게 이월
- 전원·배터리·열 상태를 고려한 실행

## 7. P2 — 같은 모델의 작업 성공률 높이기

- [ ] 실패 유형별 retry와 replanning
- [ ] 복잡한 검색 요청의 query decomposition
- [ ] 출처 품질·관련도 기반 검색 결과 reranking

- [ ] 확신이 낮을 때 질문하거나 안전하게 중단하는 기준

| 수준 | 범위 | 예시 |
| --- | --- | --- |

## 8. Benchmark 시스템

Benchmark는 Kit 개발 이후가 아니라 구현 전부터 구축한다.

### 8.1 고정 조건

- [ ] 테스트 데이터셋과 버전
- [ ] 모델·Quant·context 크기
- [ ] temperature, seed와 sampling 설정
- [ ] 시스템 프롬프트와 도구 목록
- [ ] 최대 token, 시간과 재시도 횟수
- [ ] 성공·부분 성공·실패 판정 기준
- [ ] 테스트별 반복 횟수
- [ ] 사람이 평가하는 항목과 자동 평가 항목 구분

### 8.2 측정 항목

- 완전 성공률
- 부분 성공률
- 결과 검증 통과율
- 입력·출력·전체 token
- 전체 수행시간과 최초 결과 시간
- tool-call 횟수
- 실패·재시도·재계획 횟수
- peak RAM과 에너지 사용량
- 사용자 승인 요청 횟수
- 잘못된 변경 또는 위험 행동 횟수

### 8.3 비교 형식

```text
Qwen XXB 기본
- 성공률: 61%
- 평균 token: 8,200
- 평균 수행시간: 94초
- 평균 tool-call: 7.1회

Caffeine Kit
- 성공률: 78%
- 평균 token: 6,400
- 평균 수행시간: 81초
- 평균 tool-call: 5.3회
```

### 8.4 Benchmark 과제군

- [ ] 파일 찾기·수정·검증
- [ ] 메일 분류·요약·답장 초안
- [ ] 일정 충돌 탐지와 일정 초안
- [ ] 여러 출처를 사용하는 웹 조사
- [ ] 실패하는 명령의 원인 파악과 복구
- [ ] 긴 문맥에서 핵심 요구사항 유지
- [ ] 권한이 제한된 상황에서 안전한 대안 제시
- [ ] 악성 문서나 prompt injection이 포함된 작업
- [ ] 중단 후 재개하는 장기 작업

Benchmark 결과는 평균만 공개하지 않고 샘플 수, 분산, 실패 사례와 재현 방법도 함께 제공한다.

```text
→ ⑤ 권한·감사 로그·Undo와 Daily Briefing

→ ⑪ 사용자 확보와 반복 사용 검증

```

가장 중요한 단기 목표는 **아무것도 모르는 사용자가 5분 안에 자기 Mac에서 모델과 대화하도록 만드는 것**이다. 그다음 목표는 **Mac의 정보를 연결하고 승인 기반으로 실제 일을 처리하게 만드는 것**이다. Kit과 수익화는 이 두 경험이 안정적으로 작동하고 성능 향상을 수치로 증명한 뒤 확장한다.
